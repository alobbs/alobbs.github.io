### There continue to be reasons for software to be slow

The author argues that LLMs can reduce the cost of performance optimizations, but the claim that software will no longer be slow is flawed because key assumptions often fail in practice. Tolerance for slowness tends to increase—such as with monorepo git performance and LLM autocomplete latency—meaning expectations shift rather than demand speed. Despite supporting performance work, the author remains skeptical of broad predictions that LLMs will eliminate slow software.

### Compile-Time Improvements in LLVM 23

LLVM 23 achieved a -6.75% compile-time improvement in -O3 builds, driven by optimizations to hash tables (linear probing, compact occupancy, xxh3 hashing), SmallVector's grow path, and dominator tree representation/construction (child-sibling storage, edge lists, avoiding successor materialization). These changes reduce allocations, improve cache behavior, and enable better inlining.

- [Compile-Time Improvements in LLVM 23](https://aengelke.net/llvm23-ct.html) — *aengelke.net*
