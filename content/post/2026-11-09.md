### AI agents are leaking their owners’ secrets on GitHub: thousands of files exposed

Apiiro found 2,539 exposed secrets across 1,994 public GitHub repositories in Claude Code configuration files, largely because developers approved commands with “Yes, and don’t ask again,” causing credentials to be saved in `.claude/settings.local.json`. Claude coauthored commits that exposed real secrets in 539 of 1,105 affected repositories, and tools like Gitleaks often miss secrets embedded in commands. Developers should rotate exposed credentials and keep agent memory and configuration files out of source control.

### Next-Concept Modeling: Fast, Parallel Coarse-to-Fine Text Generation

Next-Concept Modeling (NCM) is a two-stage, coarse-to-fine text generation framework that encodes text into a hierarchy of discrete codes and uses a transformer to predict all codes within each level in parallel. At matched parameter scales, NCM achieves better generative perplexity than the strongest diffusion language model baseline on LM1B while running 21× faster, and it is competitive on OpenWebText at 10× faster and matches ROUGE-L on XSum at 31× faster. NCM also outperforms autoregressive and diffusion baselines on Sudoku reasoning across all difficulty levels using fewer function evaluations.

- [Next-Concept Modeling: Fast, Parallel Coarse-to-Fine Text Generation](https://arxiv.org/abs/2610.14162) — *arxiv.org*

### What is malloc doing, anyway?

The article explains how `malloc` offers a simple allocate/free interface while glibc typically satisfies many small allocations by growing the process heap with `brk`/`sbrk` instead of making a syscall for every request. In an example, 1,000 `malloc(16)` calls caused only two `brk` syscalls: one to query the program break and one to extend the heap by 132 KiB. It also reviews the process address space and shows how a simple bump allocator can be built using `sbrk`.

### A C++ Quicksort Faster Than std::sort

It is available on GitHub under the MIT license as C++ and single-header C versions, including multithreaded variants, and efficiently handles sorted, reverse-sorted, and duplicate-heavy inputs.
