### Mini-AGI Continual Learning on 8GB VRAM

Mini-AGI is a toy-level continual-learning byte-level language model that trains from scratch on a single 8GB VRAM GPU using a batch-1 continuous data stream, storing weights on disk and paging them into VRAM so capacity is bounded by disk space. It uses a mixture-of-experts approach that grows and prunes experts during training, shares the same code path for reading/training and generation, and aims to avoid catastrophic forgetting on consumer hardware. Its weights are not yet released because the run is still completing its first pass over a 7.8-billion-character corpus.

- [A Continual learning model trained from scratch on 8GB VRAM laptop with batch-1 stream of data](https://github.com/volotat/mini-AGI/) — *github.com*

### Why back propagation goes backward

The article explains why backpropagation uses a backward pass to compute neural network gradients: the chain rule requires information from downstream nodes that is only available after the forward pass has reached them. While derivatives can be computed locally, a purely forward algorithm cannot calculate weight gradients before all dependent downstream values and derivatives exist. Backward propagation therefore efficiently reuses intermediate terms to compute gradients for every weight.

- [Why back propagation goes backward](https://gregorygundersen.com/blog/2018/04/15/backprop/) — *gregorygundersen.com*

### Windows Dangling COM Object Registration Exploitation

Microsoft fixed CVE-2026-66804, a Windows privilege-escalation flaw identified as an incomplete fix for CVE-2026-50343 (“Dark Elevator”). The bug involved a dangling system-wide COM registration for a CrossDevice object pointing to a missing DLL in the user-writable C:\ProgramData path, allowing an attacker to plant a malicious DLL. With the earlier InstallService abuse patched, the researcher demonstrated loading the DLL into a privileged process via custom COM marshaling.

- [Windows Exploitation Techniques: Dangling COM Object Registrations](https://projectzero.google/2026/09/windows-dangling-com.html) — *projectzero.google*

### Your Certificate Monitoring Can Work Perfectly and You Can Still Have an Outage

Expiration monitoring can alert teams correctly yet still fail to prevent outages because it only handles detection, not the full certificate lifecycle. Renewing a TLS certificate is a multi-step workflow—Detect → Renew → Deploy → Reload → Verify—and deployment or reload failures can cause production issues even after renewal succeeds. This gap is why the article argues for “CertOps,” which focuses on ensuring renewed certificates are actually deployed and verified.

- [Your Certificate Monitoring Can Work Perfectly and You Can Still Have an Outage](https://hackernoon.com/your-certificate-monitoring-can-work-perfectly-and-you-can-still-have-an-outage) — *hackernoon.com*

### Thinking, Fast and Slow

Thinking, Fast and Slow is a 2011 popular science book by psychologist Daniel Kahneman that distinguishes between fast, intuitive “System 1” thinking and slower, deliberative “System 2” thinking. The book summarizes decades of research on cognitive biases, judgment, and loss aversion, and it became a New York Times bestseller and winner of the 2012 National Academies Communication Award. Some priming studies cited in the book have since been questioned during the psychological replication crisis.

- [Thinking, Fast and Slow](https://en.wikipedia.org/wiki/Thinking,_Fast_and_Slow) — *en.wikipedia.org*

### Winning the Visa Lottery

A study using randomized H-2B visa lotteries found that US firms denied low-skill foreign workers cut their H-2B employment roughly in half, while revenue and investment fell; firms able to hire more such workers saw higher revenue and investment. Crucially, losing firms did not increase employment of low-skill American workers, suggesting that restricting foreign low-skill labor shrinks businesses without creating jobs for natives.

- [Winning the Visa Lottery](https://www.aeaweb.org/research/immigration-restrictions-firms-workers) — *aeaweb.org*

### Can I Let My AI Agent Run on Shabbat?

The article explores whether an AI agent may be allowed to run autonomously on Shabbat, arguing that although the technology is new, the underlying halachic issues are not. It compares the case to earlier debates over water mills and vending machines, including concerns about noise, the appearance of work, and transactions taking place on Shabbat. It notes that noisy machines generally should not be left running on Shabbat, while cases involving financial transactions require separate analysis.
