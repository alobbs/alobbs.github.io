Debugging Type-Based Alias Analysis optimizations in BPF

A BPF program started producing bad L3 checksums after switching to vmlinux.h. The root cause was Clang’s strict aliasing optimization: since iph->tos and a uint16_t* pointer have different types, the compiler assumed the memory hadn’t changed and reused the old value instead of rereading it after the write. The fix is to compile with -fno-strict-aliasing or adjust the code to avoid the aliasing issue.

  • Debugging Type-Based Alias Analysis optimizations in BPF — loshz.com
